01 · Overview

What this is

A single-page developer site at a custom domain, built with Astro and served from S3 through CloudFront, with all AWS infrastructure provisioned by Terraform. The page carries a header, an About section, and a “Stuff I’ve made” grid of project cards. Both content sections ship as skeletons and get filled in later.

The site is the hub for other projects. Some cards link to apps hosted on their own subdomains, some to GitHub repositories only. This spec covers the shared platform layer and the site. Each hosted app gets its own brainstorm, spec, and plan.

Scope in: the Astro site, Terraform bootstrap and platform layers, a reusable static-site module, the portfolio stack, and the GitHub Actions deploy path.
Scope out: the recipe app, the RAG system, the capstones, and any compute or database infrastructure. The RAG system links to its repository and is not deployed.

02 · Decisions

The four ADRs

Each one records what was chosen, what credible alternative it beat, and why. These are the study material.

ADR 0001

Astro as the static site generator

Content collections for projects, About, and header config. Zod schemas fail the build on a bad entry.

Beat plain HTML (no schema, hand-optimized images) and Eleventy (no image pipeline). Cost: a Node toolchain for a one-page site.

ADR 0002

GitHub-hosted runner with OIDC

No stored AWS credentials. STS issues a one-hour credential per run, scoped to one bucket and one distribution.

Beat a self-hosted runner on the home server. OIDC works identically there, so nothing technical is lost, but no constraint forces it: a 20-second build against 2,000 free minutes, and nothing needs the private network. Self-hosting would add runner maintenance and a fork-PR path into the home network.

ADR 0003

Terraform topology and per-app subdomains

Bootstrap, platform, modules, stacks. S3 backend with native locking. One subdomain and one distribution per app.

Reverses an earlier “no child modules” call that was right for one site and wrong for four apps. Beat path-based routing on a shared distribution, which couples every deploy to one resource. Beat a DynamoDB lock table, deprecated since Terraform 1.10.

ADR 0004

Porting the html_artifacts visual identity

The site becomes a second implementation of the same palette table, with three deliberate divergences: font delivery, three contrast values, and no theme toggle.

Beat copying artifacts.css wholesale, which drags in document furniture the site never uses. Beat a shared npm package, more machinery than a 20-line CSS block deserves.

A fifth ADR on home-server hosting for dynamic apps was drafted and then dropped. The recipe app already splits into a seeded demo with no backend, which is static, and a live instance reachable only over Tailscale, which is private. Nothing public needs compute, so the premise dissolved. ADR number 0005 stays retired; the next one is 0006.

04 · Site

Architecture

Content model3 collections

All schema-validated at build time. Config at src/content.config.ts, loaders from astro/loaders, zod from astro/zod.

const projects = defineCollection({
  loader: glob({ pattern: '**/*.md', base: './src/content/projects' }),
  schema: ({ image }) => z.object({
    title: z.string(),
    blurb: z.string().max(120),
    stack: z.array(z.string()).default([]),
    year: z.number().int(),
    order: z.number().int(),
    thumb: image().optional(),
    live: z.string().url().optional(),
    repo: z.string().url().optional(),
    draft: z.boolean().default(false),
    placeholder: z.boolean().default(false),
  }).refine(d => d.live || d.repo, {
    message: 'a project needs a live URL, a repo URL, or both',
  }),
});
  • Ordering. order is required, no default, no tiebreaker. Number sparsely by tens so inserting means 15, not renumbering. year is displayed and never sorted on, which preserves leading with an older project without editing its year.
  • Link types are derived, not declared. No type field. A Live chip appears when live exists, a Source chip when repo does, and the refine fails the build on an entry with neither. An unfinished project omits live and gains it in one line when it ships.

Styles and the skeleton state2 files

tokens.css holds the ported palette, the prefers-color-scheme override, and the Anton @font-face, and nothing else. site.css holds layout: the wrap, header grid, portrait panel, card grid, responsive collapse. Keeping them separate is what makes the token contract legible rather than a claim.

The skeleton uses two mechanisms, neither a separate render path:

  • A placeholder boolean shared by about.md and the seed project entries. When true, Stub.astro wraps the content in the dashed .block-stub frame and prints the file that replaces it. Deleting the flag deletes the treatment.
  • A missing thumb renders the blueprint panel and a mono “no image yet” label. This keys off the absent field rather than the flag, so a real project without a screenshot degrades the same way instead of looking broken.

05 · Infrastructure

Terraform

Everything in us-east-1, single provider, no alias. ACM for CloudFront must live there and nothing else here is region-sensitive, so pinning removes an alias and a common class of “certificate not found” errors.

infra/
├── bootstrap/          local state, run once by hand
├── platform/           zone lookup, ACM cert, OIDC provider, budget alarm
├── modules/
│   ├── static-site/    bucket + OAC + distribution + record + deploy role
│   └── lambda-app/     (later)
└── stacks/
    ├── portfolio/
    └── <app>/          one thin root module per app
bootstrap and platformapplied by hand
  • bootstrap. Local state. Creates the state bucket with versioning, SSE, public access blocked, and prevent_destroy. Its terraform.tfstate is a real file on disk and must be gitignored.
  • Zone. data "aws_route53_zone" looking it up by name. Never creates it, so no plan can touch the NS records.
  • Certificate. Apex as domain_name, *.domain as a SAN, because a wildcard does not match the apex.
  • OIDC provider for token.actions.githubusercontent.com, thumbprint from data.tls_certificate rather than a pasted hex string.
  • Budget alarm at a low monthly threshold. This is the deliberate observability choice: CloudFront access logs would cost S3 storage and go unread, while a budget alarm reports the one thing that matters on a free-tier account.
The static-site modulereused later
  • Bucket with all four public access block flags true and ownership controls set to BucketOwnerEnforced, so ACLs are off entirely.
  • Origin Access Control, not the legacy OAI. The bucket policy grants s3:GetObject to cloudfront.amazonaws.com only, conditioned on AWS:SourceArn matching this distribution. That condition is what stops any other distribution in any account from reading the bucket.
  • Distribution with default_root_object, redirect-to-https, compression, the managed CachingOptimized policy, and PriceClass_100.
  • A response headers policy carrying HSTS, X-Content-Type-Options, Referrer-Policy, and a CSP.
  • A CloudFront Function issuing a 301 from www to the apex.
  • Route 53 A and AAAA alias records using the distribution’s own hosted_zone_id attribute, not the hardcoded Z2FDTNDATAQYW2 half the tutorials paste in.
  • A deploy role assumable only through OIDC, scoped to three S3 actions on one bucket and cloudfront:CreateInvalidation on one distribution.

06 · Deploy

Push to main

Terraform does not run in CI. Static analysis does, because it needs no credentials. Plan and apply stay local and manual.

on:
  push:
    branches: [main]
    paths: ['site/**', '.github/workflows/deploy.yml']
  workflow_dispatch:
concurrency: { group: deploy, cancel-in-progress: false }
jobs:
  deploy:
    permissions: { id-token: write, contents: read }
  • Steps: npm ci, astro check, astro build, assume role, sync, invalidate.
  • Two sync passes, and the order is load-bearing. Hashed assets first with max-age=31536000, immutable; HTML second with max-age=0, must-revalidate. HTML uploaded before the files it references produces a page that 404s on its own stylesheet for the length of the second pass.
  • Invalidation uses /*, which counts as one path against the 1,000 free paths per month.
  • The role ARN lives in a repository variable, not a secret and not hardcoded, so the same workflow shape drops into later app stacks with one value changed.
  • cancel-in-progress: false, because killing a half-finished sync leaves the bucket in a mixed state.

07 · Verification

How you know it works

What the build already guaranteesfree

The zod schema fails astro build on a malformed entry, including the refine rejecting a project with no links. astro check catches type errors. That is most of the correctness surface, at zero test code.

What gets a test, and what does not1 unit
  • Tested: sortProjects(). Drafts excluded, order respected. A sort that silently breaks is invisible in review, which is the whole argument.
  • Not tested: component rendering. Asserting that ProjectCard renders the title it was passed tests Astro, not this code.
  • Not used: Terratest. Fifteen resources with one consumer, already proven by the checks below.
  • Automated: Playwright with @axe-core/playwright in both themes, protecting the contrast decisions from a future token edit. Playwright rather than the axe CLI because verifying dark mode needs emulateMedia({ colorScheme: 'dark' }). The same suite asserts the built page loads no JavaScript.
  • In CI: terraform fmt -check, validate, and tfsec. No credentials, no state.
Infrastructure checks, run by hand after apply6 
curl -sI https://<domain>                     # 200, HSTS present
curl -sI http://<domain>                      # 301 to https
curl -sI https://www.<domain>                 # 301 to apex
curl -sI https://<bucket>.s3.amazonaws.com/index.html   # 403
aws s3api get-public-access-block --bucket <name>        # all four true
dig +short <domain>                           # CloudFront edges
The 403 is the one to run twice. It separates “the site works” from “the site works and the bucket is not readable by anyone else,” and it is the check people skip.

Neither one is fixed by changing its value.

  • --accent also carries the wordmark period, the kicker marks, the list chevrons, and the accent borders, none of which are text. Darkening it to clear AA would dull all of that to fix one use. The site keeps #e8611c and adds --accent-text at #b84a10 (4.79:1) for links and accent-colored text. Dark needs no change.
  • --ink-faint cannot be fixed by value at all. Clearing AA on this background lands around #6f6c62, and --ink-dim is #6d6a61. They collapse into one color. So the value stays and the usage changes: text moves to --ink-dim, and --ink-faint survives for non-text ornament.

08 · Acceptance

Success criteria

  • https://<domain> serves the page over HTTPS with HSTS present
  • The direct S3 URL returns 403
  • A push to main touching site/ deploys with no stored AWS credential
  • Adding one markdown file to src/content/projects/ produces one card, with no other edit
  • The skeleton state renders as deliberately unfinished and names the files that replace it
  • Light and dark both pass axe with zero violations
  • The built output contains no JavaScript
  • terraform plan on a clean tree reports no changes

09 · Before anything runs

Manual prerequisites

  • Register the domain. Route 53 creates the hosted zone automatically; another registrar means creating the zone and repointing nameservers.
  • git init and create the GitHub repository, public. The repo name and owner get baked into the OIDC trust policy.
  • An AWS account with a local admin-capable profile for the bootstrap, platform, and portfolio applies.
  • Node 22.12 or newer, required by Astro 7.
  • Terraform 1.10 or newer, required for use_lockfile.
Known future directions4

Recorded so the current design does not fight them. None are in scope.

  • Hosted apps at their own subdomains, consuming platform outputs (ADR 0003).
  • The recipe app’s demo mode (seeded data, no backend) as the second consumer of static-site. That is the real test of whether the module’s boundaries are right, since a module with one consumer is a guess.
  • A lambda-app module alongside static-site if a public serverless app ever arrives. Nothing currently planned needs one.
  • A scheduled link checker once project entries carry external URLs worth rotting.
Implementation split2 plans

The site gets a normal implementation plan, executed for you.
